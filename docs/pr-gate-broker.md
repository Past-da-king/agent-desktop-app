# PR gate: credential broker proposal

25 November 2026. Future option only, not built or planned for this release. The main agent selected a cooperative workflow guard; restricted identities and credential migration are out of scope. Supersedes the round-seven shell/shim security boundary. This note is not a release candidate or implementation plan. No merge or release.

## Threat model and required boundary

Prevent an agent from sending a half-vetted PR to a reviewer through gh, git, REST, GraphQL, computed commands, interpreter files, absolute executable paths, login shells or another linked brain. Ordinary development must continue. Shell parsing supplies an early explanation only; it cannot authorise an operation or provide security.

The broker never returns a usable GitHub credential to an agent, including through a git credential-helper response. Existing personal access/OAuth tokens cannot be narrowed to one HTTP operation by issuing them on demand. A host/path-only credential request cannot distinguish a draft create from a merge. Therefore the broker must execute the actual authenticated request itself, after inspecting its method, canonical destination and complete body.

Critical prerequisite: unrestricted code running as the same OS user as the existing gh login can read its files, invoke its credential manager or use another signed-in shell. Empty GH_CONFIG_DIR and environment scrubbing alone do not prevent this. Strong enforcement requires agents to run under a separate restricted OS principal, with no access to the broker process, its credential store, the owner home/keychain, SSH keys that reach unisolated signed-in accounts, or a privileged shell/device tool. On Linux/WSL this means a separate UID and protected broker storage; on Windows a separate restricted account/token and ACL-protected broker storage. All app shell, interpreter, engine, worker and device execution paths must use that identity. Administrative escape paths must be unavailable to that agent identity. If that isolation is not approved or cannot be established, this feature can only be labelled a cooperative workflow guard, never an unbypassable credential gate.

## Credential location and request flow

Each brain has its own broker, running outside the agent principal. Its encrypted credentials remain in the owner credential store, accessible only to the broker/owner. Tokens never enter the agent environment, argv, disk, logs or API responses. Broker credentials are not replicated. Agent processes receive an empty private GH_CONFIG_DIR and no GH_TOKEN/GITHUB_TOKEN or equivalent inherited auth. Each WSL distribution is enrolled separately; wsl itself is not wrapped and keeps its normal semantics.

A local authenticated IPC endpoint accepts bounded operation requests from enrolled agent sessions. Its capability identifies the actor, chat, profile and request, and is useless at GitHub. It never means that all subsequent writes are approved. The broker checks the final operation, account, repository, PR, current head and exact payload against the same attestation policy immediately before execution. One-shot grants bind those values and expire; changed payloads or another inner call need their own grant. Remote operations use the destination brain broker and authenticated request-carried provenance, not a caller-supplied approval boolean.

* **gh:** an argument-preserving native launcher/client translates supported commands to broker operations. It does not use a Windows batch wrapper, BASH_ENV or a WSL launcher. Generic gh api requests carry the exact REST/GraphQL operation to the broker. Unsupported authenticated commands explain that support is missing; they never obtain a token. Absolute real gh and computed wrappers have no credentials and cannot authenticate. Preserve stdin, binary stdout, stderr, cancellation and exit codes. Commands that export credentials, install extensions or run arbitrary aliases are not broker operations.
* **REST:** the app tools and explicit broker HTTP client submit method, path, query and body. The broker only contacts configured GitHub API hosts over validated TLS, attaches auth internally, refuses redirects to other origins and never forwards caller authentication. Arbitrary curl/python calls directly to GitHub remain unauthenticated. Response/error redaction and credential-export endpoints prevent token disclosure.
* **GraphQL:** parse the document and select operationName, variables and every mutation field, including aliases, fragments and batches. Reads pass. An unknown mutation is held with a precise explanation. Never classify by the word mutation or a substring alone. Do not allow GraphQL to invoke a second uninspected operation.
* **git:** use a credential-free broker transport/remote-helper that streams smart HTTP through the broker. A conventional credential helper must not return the owner's token. The helper can identify the local broker transport and report configuration errors, but does not supply reusable Basic auth. Reads, clones, fetches and branch pushes pass automatically; their transport pack streams remain binary and bounded independently of JSON request limits. This PR gate does not add an attestation requirement to branch pushes. Direct protected-branch policy remains GitHub's responsibility. Agent SSH remotes use the broker transport or fail with a migration message; giving agents an existing GitHub SSH key would bypass the gate.

## Operation policy

Automatically permit authenticated reads, release lists, clones, fetches, branch pushes and PR creation whose actual body explicitly sets draft=true. Ordinary commands without GitHub activity remain untouched. Do not hold shell pipelines, feature pushes, multiline draft bodies or comments merely because their command text is opaque.

Require a valid attestation for non-draft PR creation, draft-to-ready transitions, merge operations, review approvals, review requests and comments announcing Ready for review. Resolve issue-comment targets to their PR before policy evaluation. Inspect REST bodies and GraphQL input, not command spelling. Unknown PR-changing operations are held for classification; unrelated supported writes retain their existing approval policy. Read responses, extension/alias execution and arbitrary subprocess facilities must never become a credential-export route. Check every operation separately, including multiple mutations in one request, and record the decision without secrets.

Existing attestation checks still verify exact head, testing/review proof and combined-PR trial requirements. The parser cannot turn a broad outer approval into permission for inner writes. GitHub identity remains per repository/account, with an explicit account binding in every broker request.

## Migration, recovery and rollback

1. Inventory auth sources on each enrolled Windows/Linux/WSL brain, including gh config, environment, git helpers, SSH remotes and keys. Import existing owner-approved logins into broker custody without printing tokens or requiring a new GitHub App. Preserve owner interactive gh/git configuration outside the restricted agent identity.
2. Establish and verify OS isolation before claiming enforcement. Create empty agent gh stores, remove inherited credential access, install the credential-free gh/git clients, and enrol linked brains. Existing owner sessions keep working. An unconverted brain must not execute authenticated agent GitHub work through the owner's account.
3. Prove representative private reads, clone/fetch, feature push, draft create, preserved argument/stream/exit behaviour, and denial of computed REST/GraphQL/absolute-gh/SSH bypasses. No real merge or reviewer notification is used as a test. Tests use isolated HOME/config and fake transports so profile scripts cannot find a real gh login. Compile tests before running them after 08:30 SAST on Thursday 26 November 2026.
4. Separately repair replication bootstrap: recover a missing peer authority row from the fingerprint-pinned peer's authenticated self-description after join/reset/restore, without locally restamping or replicating a stale host snapshot. Protect device address/fingerprint authority as well as roles/key fields; retry a held page without advancing its cursor, and expose authority recovery status. Test an empty/reset store and concurrent changes through the real via/trust path.
5. Rollback disables agent authenticated GitHub execution first, then removes broker routing and restricted sessions. Restore ordinary owner configuration only to the owner session; never put credentials back into an active agent environment. Key custody/export changes require owner approval and an audit row. In-flight requests cancel or finish under their original exact-operation decision.

## Explicit limits and approval requested

No GitHub App is needed, but neither PATs nor the Git credential protocol alone supply the required operation isolation. The meaningful implementation includes OS identity isolation and credential-free transport, not just another shim. Owner/manual processes, credentials deliberately supplied outside broker custody, other machines not enrolled, and GitHub web sessions outside the gate remain outside its boundary. Owner-equivalent unrestricted shell or browser access makes a strict guarantee impossible; broker credentials and a signed-in GitHub browser must not be reachable through those tools by the restricted agent.

Decision: retain this as a future design note only. This release does not change credential custody, owner identities or existing logins.
