# M12: Windows-native correctness and the environment scan

Why: the app must run natively on Windows with whatever the person already has (PowerShell 5.1 or 7, cmd, Node, Python, Git, and AI tools such as Claude Code,
OpenCode, Gemini CLI, Codex or Antigravity installed as npm shims or normal programs). It must NEVER assume WSL, bash, python3, a particular Node, or that any tool exists.
It must NEVER install anything on the person's computer. It looks first (scan), tells the person what it found, and uses only what is there.
A real Windows 11 machine behaves like this (measured): PowerShell 5.1 only (no pwsh), `node` at C:\Program Files\nodejs\node.exe, Python launcher `py.exe` plus `python.exe`,
`git.exe`, npm global CLIs as `claude.cmd` / `claude.ps1` and `opencode.cmd` / `opencode.ps1` in %APPDATA%\npm, `code.cmd`, and `wsl.exe` present but not wanted.
Everything below must be testable on Linux by injecting the platform, but will also be run for real on Windows by Claude afterwards.

Read first: PLAN.md sections 5.3 and 7, `apps/desktop/src/main/tools/{shell,code,files}.ts` and their tests, `apps/desktop/src/main/tray.ts`.

## Build this
1. `apps/desktop/src/main/runtime/environment.ts` (pure, dependency-injected: `platform`, `env`, `fs.exists`, `exec(file,args,{timeoutMs})`, `now`):
   - `resolveCommand(name, deps)`: finds an executable on PATH honouring Windows `PATHEXT` (.COM;.EXE;.BAT;.CMD;.PS1 and others), case-insensitive on Windows, skipping directories and the Windows Store app-execution-alias stubs (zero-byte files under `WindowsApps` that are not real programs).
     Returns `{path, kind: 'exe'|'cmd'|'ps1'|'script'}`. On Linux/macOS honours the exec bit.
   - `scanEnvironment(deps)` returns `EnvironmentReport { os: {platform, release, arch, hostname}, shells: Found[], runtimes: Found[], aiTools: Found[], notes: string[], scannedAt }`, where `Found = {id, label, found: boolean, path?, version?, kind?}`.
     Shells: on Windows `pwsh`, `powershell`, `cmd`; elsewhere `bash`, `zsh`, `sh`. Also report `wsl` as informational on Windows (never required, never used).
     Runtimes: `node`, `python` (try `py -3`, `python`, then `python3`; on Windows ignore the `python.exe` Store stub), `git`.
     AI tools: `claude` (Claude Code), `opencode`, `gemini`, `codex`, `antigravity` (also look for its usual install folder names on each OS without hardcoding any user name: use env vars like LOCALAPPDATA, APPDATA, HOME).
     Versions: run `<tool> --version` with a 4 s timeout, in parallel, parse the first version-looking token, never throw; a tool that hangs or fails is `found: true` with no version.
     Nothing in the scan writes, installs, signs in, or sends anything anywhere.
   - Cached for the session; `environment.scan({refresh})` re-runs.
2. IPC: add `environment` group to `packages/core/src/ipc.ts` (additive): `scan(refresh?: boolean): Promise<EnvironmentReport>`. Types go in ipc.ts. Preload, main handler and the mock bridge (mock returns a Windows-like report: PowerShell 5.1, Node, Python, Git, Claude Code, OpenCode found; Gemini not found).
3. UI: Connections > "This computer" card lists what was found in three groups (Shells, Runtimes, AI tools) with a found / not found marker, version, and a "Scan again" button; a not-found tool shows plain text "Not found on this computer", never a download link or an install button.
   Settings > "This computer" gets the same compact summary. Neutral wording, no advertising.
4. System prompt: add a short block `THIS COMPUTER` listing OS, the shell the shell tool will use, and the found runtimes and AI tools (names and versions only, no paths with user names), plus the rule: only suggest or use tools that are listed as found; never tell the person to install something unless they ask.
5. `shell_run` (tools/shell.ts): pick the shell from the scan, not from assumptions. Windows order: `pwsh` if found, else Windows PowerShell (`powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -Command`), else `cmd.exe /d /s /c`. Other OS: the user's `$SHELL` if it exists, else `sh`. A `shell` argument may pick `powershell`|`cmd`|`bash` only if found.
   Force UTF-8 output on Windows PowerShell (set `[Console]::OutputEncoding` and `$OutputEncoding` inside the command wrapper; for cmd run `chcp 65001 >nul` first). Kill the whole process tree on abort/timeout: `taskkill /PID <pid> /T /F` on Windows, process group on POSIX. cwd must be a real directory (Windows drive letters and UNC allowed); a bad cwd returns a plain-words error.
   The approval card shows the exact command AND which shell will run it. Env stripping of /KEY|TOKEN|SECRET|PASSWORD/i names must be case-insensitive and must also drop `ELECTRON_RUN_AS_NODE`.
6. `spawnResolved(command, args, opts)` helper (new file `runtime/spawn.ts`) used by every place the app starts an external program: resolves via `resolveCommand`; `.exe` is spawned directly with `shell:false`; `.cmd`/`.bat` are run through `cmd.exe /d /s /c` with correct quoting (this is required on current Node, spawning a .cmd directly throws EINVAL); `.ps1` through `powershell.exe -NoProfile -ExecutionPolicy Bypass -File`. Arguments with spaces, quotes, `&`, `%` and `^` must survive; unit test the quoting with a table of nasty arguments by running a tiny echo script through each path on the host platform AND by testing the quoting function with an injected `platform: 'win32'`.
7. `run_code` (tools/code.ts): JavaScript runs with the person's `node` if the scan found one, otherwise with the app's own runtime (`process.execPath` with `ELECTRON_RUN_AS_NODE=1`, so JavaScript always works with nothing installed). Python uses the scan (`py -3`, `python`, `python3`); if none is found, the tool returns a plain sentence saying Python was not found on this computer and does not try to install it. Temp folders via `os.tmpdir()`, paths quoted properly.
8. `files_*` tools (tools/files.ts): path handling must be correct for Windows when `platform === 'win32'` (use `path.win32` in the injectable path layer): drive letters, UNC paths, `\\?\` prefix, mixed slashes, trailing dots and spaces, reserved device names (CON, PRN, AUX, NUL, COM1-9, LPT1-9), alternate data streams (`file.txt:stream`), 8.3 short names resolved through `realpath`, junctions and symlinks resolved with `realpath` before the granted-folder check, comparisons case-insensitive on Windows and case-sensitive elsewhere. Add tests simulating Windows with an injected path module and fake fs.
9. Other Windows details: settings/DB/logs/secrets live under `app.getPath('userData')` only (never hardcoded `~/.agent`); the window title bar and tray work with Windows DPI scaling; `launchAtLogin` uses `app.setLoginItemSettings` with the packaged exe path; notifications use the app user model id (`app.setAppUserModelId`) set from the single APP_NAME / app id constant so toasts show the app name; paths shown to the person use the OS separator; line endings in files the agent writes are preserved as given.
10. Never hardcode anything personal: no user names, machine names, drive letters, install paths, URLs in the source. Tests use synthetic names like `C:\Users\tester`.
