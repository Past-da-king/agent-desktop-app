# M5: Onboarding live

Goal: the four onboarding steps do real work through `window.agent`.

Read first: `design/mockup.html` lines 707-794, `apps/desktop/src/main/account.ts`, `packages/core/src/ipc.ts`.

## Build this
- Sign in step: Sign in / Create account (segmented). Email + password (>= 6), show/hide, inline errors from the server in plain words
  (409 "There is already an account with that email. Try signing in.", 401 "That email and password do not match.", network "Could not reach the sync server. Check the address, or use this computer only.").
  An "Advanced" disclosure with "Server address" (https required unless the user ticks "Allow unencrypted HTTP"). If `syncUrl` is empty and the user tries to sign in, show the explanation and focus the field.
  "Use this computer only, no account" skips to the AI step with `signedIn:false`. The QR card is disabled "Coming soon".
- Sync step: runs `account.firstSync()`, shows the mockup's animated rows with REAL counts from `account.onProgress` (rows tick off as their kind arrives), error state with Retry and "Skip for now".
  If this computer only, the step is skipped automatically.
- AI step: provider chips from `settings.providers()`, model field prefilled with the provider default (editable), key field (show/hide; the key is sent to `settings.setApiKey` and never kept in React state after submit),
  "Check key" calls `settings.checkKey()` and shows ok/failed with the message; "Continue" requires a passing check OR an explicit "Skip, I will add it later" link. Subscription rows disabled "Coming soon". Custom provider reveals base URL + http opt-in.
- Style step: your name, agent name, accent swatches, mascot picker, live preview card; "Open Agent" saves settings with `onboarded: true`, then routes to Home with the agent mascot waving in.
- Back/Next between steps with the progress dots; state survives a reload mid-onboarding (current step in settings or sessionStorage).
- If already signed in (token exists) the sign-in step shows "Signed in as <email>" with Continue and "Use a different account".

## Accessible-name contract (scripts/shoot.mjs drives the flow with these; do not rename)
- Sign in step: a `role="tablist"` segmented control with tabs named "Sign in" and "Create account"; inputs labelled "Email" and "Password"; submit button named exactly "Sign in" or "Create account" (matching the active tab);
  inputs labelled "Server address" (inside Advanced). The step does not auto-advance: on success it goes to the sync step.
- Sync step: a button named exactly "Continue", enabled when the sync finished (or failed and was skipped). No auto-advance.
- AI step: one button per provider whose name contains the provider label (e.g. "Anthropic"); input labelled "API key"; model input labelled "Model"; button "Check key"; button "Continue".
- Style step: inputs labelled "Your name" and "Agent name"; button "Open Agent".
- After "Open Agent" the route hash is `#/home`.

## Tests
Renderer-side vitest with jsdom is NOT required. Add `apps/desktop/test/onboarding-flow.test.ts` that drives the main-process services (`AccountService` + fake sync server): register -> firstSync progress events -> settings saved -> onboarded.
