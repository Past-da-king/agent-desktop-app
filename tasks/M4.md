# M4: Renderer foundation: every screen, on the mock bridge

Goal: the whole mockup, ported to React, looking identical, running in a plain browser on the mock bridge and inside Electron on the real bridge
(settings/account/data from M3 where they exist; chat is still the mock until M6). The real app starts EMPTY (PLAN.md 6.1); the mock bridge is seeded with the demo persona.

Read first: PLAN.md section 6 (the port table), `design/mockup.html` (all of it), look at every PNG in `design/shots/`.

## Build this
1. Styles: split the mockup CSS into the files listed in PLAN.md section 6, verbatim. Fonts: Roboto and Roboto Flex from Google Fonts via `<link>` in
   `index.html` (the CSP already allows `fonts.gstatic.com`; also allow `https://fonts.googleapis.com` in `style-src`), with a system-font fallback stack.
2. `ui/` primitives: `Icon` (name -> svg from the mockup's `I`), `Mascot` (all 9, with `busy` morph + eyes, `size`), `Wave`, `Ring`, `Button` (variants from the mockup:
   filled, tonal, outline, text; sizes; pill), `Field`, `Segmented`, `Switch`, `Chip`, `Eyebrow`, `SectionHeader (eyebrow + one line)`, `Skeleton`, `EmptyState`, `Dialog` (a11y focus trap, Esc).
3. `state/`: `useSettings`, `useData` (per-entity lists with `load()` + subscription to `data.onChanged`), `useUi` (view, selected ids, overlay), `theme.ts` (applies `data-theme`, accent variables).
4. `shell/`: `TitleBar` (real window controls, command-bar button opening the palette, sync pill from `account.status`, theme toggle; on macOS keep controls on the left? NO: keep the mockup's Windows layout everywhere in v1),
   `Rail` (agent card, New chat, nav with the open-needs count badge on Home, recent chats, Settings, account), `Sheet`, `Panel`, `Palette`, `QuickAsk`.
   Hash routing: `#/home`, `#/chat`, `#/tasks`, `#/memory`, `#/routines`, `#/connections`, `#/settings`, `#/onboarding/<step>`; no router library (small `useRoute` hook).
5. `views/`: Home, Chat (thread rendering for every `ChatItem.kind`: user, agent with markdown-lite, activity chips, question card, approval card, notice, report card; composer with attach, send, stop),
   Tasks (master-detail; to-dos / agent's work), Memory (search, kind filter, list, detail with `[[links]]`), Routines, Connections, Settings.
   Memory detail's link graph from the mockup is kept (pure SVG, laid out from the real `[[links]]`).
6. `onboarding/`: the four steps as static, validated UIs (wiring to real sign-in is M5). Show "Coming soon" per PLAN.md section 11.
7. `bridge/seed.ts`: the demo persona and data from the mockup arrays; `bridge/mock.ts` grown into a complete in-memory `AgentApi` (data CRUD that really mutates and fires `onChanged`,
   chat that echoes a canned agent reply after 800 ms with an activity chip, settings that persist in `localStorage` guarded by try/catch).
   The mock has four modes chosen by URL query (read once at startup):
   - no query: a fresh install. No data, `onboarded: false` (so the app routes to onboarding).
   - `?demo=1`: seeded with the demo persona and `onboarded: true`, `signedIn: true`.
   - `?demo=empty`: `onboarded: true`, no data (for empty states).
   - `?demo=big`: seeded like demo=1 plus 40+ tasks, 40+ memories, 12 routines, 60 chat messages and several very long titles (80+ characters, no spaces in one of them).
   Mock behaviours that the shoot script relies on: `account.signIn` succeeds for any well-formed input after 500 ms; `account.firstSync` emits `onProgress` counts over about 2 s and resolves;
   `settings.checkKey` succeeds for any non-empty key after 600 ms; `settings.save({onboarded:true})` works.
   In the browser, `Ctrl+Shift+Space` opens Quick Ask (in Electron the main process sends `window.onQuickAsk`).
8. Boot logic: if `settings.onboarded` is false route to onboarding, else to the last or home view.

phone layout at 820px, to-do check/uncheck with strike animation, approve/decline cards, answer chips, memory search/filter, routine toggles, Esc to close any overlay.

home, chat, tasks, memory, routines, connections, settings, onboarding steps (signin, sync, ai, style), palette, quick. Fails on console errors or horizontal overflow.
