# M0 report: Scaffold

## Built

- Root npm workspace (`packages/*`, `apps/*`), private, ES modules, Node >= 22.13, with scripts for typecheck,
  build, test, dev, dev:web, shoot and gate.
- `tsconfig.base.json` with strict, ES2022 and Bundler resolution. Every workspace typechecks with `tsc --noEmit`.
- `@agent/core` resolves to its TypeScript source (`src/index.ts`) and re-exports `ipc.ts`. One vitest case checks
  `DEFAULT_SETTINGS.shell === 'ask'`.
- `@agent/desktop` is an electron-vite project with main, preload and renderer targets.
  - Main: frameless 1280x820 window (min 360x600), secure webPreferences, single instance lock, external links
    handed to the OS, navigation blocked, real maximize IPC, and the `--smoke` mode that waits for `window.agent`
    and prints `SMOKE OK`.
  - Preload: exposes `window.agent` with `platform`, `version` and the real window group; every other group is a
    stub that rejects with "not implemented yet" (sync getters that cannot reject return an empty/no-op value).
  - Renderer: React 18, CSP meta tag, a centered "Agent" boot page using the design tokens for light and dark, and
    a mock bridge that falls back when `window.agent` is absent.
- The renderer builds to `apps/desktop/out/renderer` with relative asset URLs. `node scripts/shoot.mjs --only boot`
  produced three clean screenshots with no console errors, overflow, tiny text or contrast warnings.
- `README.md` with the run, test, screenshot and gate commands.

## Checks

`bash scripts/gate.sh M0` printed `GATE M0 PASSED`: typecheck, build, repo rules, tests (1/1), boot screenshots and
the Electron smoke run all passed.

## Notes for the next milestone

- `@vitejs/plugin-react` was added (not named in PLAN.md) because electron-vite needs a React transform plugin for
  JSX and fast refresh. It is a development-only, standard pairing with Vite and React.
- Electron 44 no longer downloads its binary during `npm install`. The first `npx electron` (or `npx install-electron`)
  fetches it, so a fresh machine needs network access before the smoke check can run.
- The mock bridge is deliberately minimal. M3/M4 should grow `bridge/mock.ts` and `bridge/seed.ts` rather than
  replacing the fallback contract in `bridge/index.ts`.
- The stylesheet is only a token placeholder for the boot page. M4 must lift the real tokens and component CSS from
  `design/mockup.html` and delete the placeholder rules that duplicate them.
- Nothing is hardcoded to a person, server or account. `Settings.syncUrl` stays empty by default.
