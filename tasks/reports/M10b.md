# M10b report: helper cards in the renderer

Status: done. `bash scripts/gate.sh M10b` prints `GATE M10b PASSED` (198 tests, 5 of them in
`helper-cards.test.ts`).

## What I built

- `apps/desktop/src/renderer/lib/helpers.ts`: one place for reading a helper's `chat_item` row.
  It exposes the helper's state, summary, brief, result and its own `activity` rows (matched on
  `meta.helper`). Visibility follows the phone: a working (or queued) helper shows in the thread; a
  finished helper stays until the main `agent` reply carrying its result has landed; a stopped
  helper folds away at once.
- `views/Chat.tsx`: replaced the placeholder helper row with a real card. It shows the label, live
  state pill, current step and a chevron. Opening it shows the brief and the helper's own steps. A
  working card has a Stop button that calls `helpers.stop(id)`. Helper activity rows are no longer
  drawn loose in the main thread; they belong inside the card.
- `views/Home.tsx`: the "Right now" card lists every helper working now, with its current step, and
  the subline says how many helpers are working.
- `shell/Palette.tsx`: "Stop all helpers" under "Do something", wired to `helpers.stopAll()`.
- `bridge/seed.ts` and `bridge/mock.ts`: the demo thread carries one working helper with two real
  activity rows and one finished helper, so both card states show in the mock and screenshots. The
  mock implements `stop` and `stopAll` by writing the same meta the main process writes.
- Contract and IPC (additive, as M10a asked): `AgentApi.helpers.stop` and `helpers.stopAll`, their
  channels, preload methods, main handlers and the helper manager passed into `registerIpc`.
- `styles/views.css`: helper card, expanded body and Home helper rows, using the existing tokens.
- `test/helper-cards.test.ts`: grouping and hiding rules, the queued state, the demo seed, and the
  mock stop controls. `ipc-contract.test.ts` now covers the two helper channels.

## Choices and deviations

- Finished cards hide on the main reply, not the instant the helper changes state, so the person
  can see a short "Done" card while the main agent writes its answer. This matches the note M10a
  left for this milestone and the phone's behaviour.
- The helper's activity is still stored as ordinary `activity` rows (M10a already writes them), so
  sync and history work unchanged. Only the renderer groups them under the card.
- No new dependencies.

## For the next milestone

- Helper ids in the UI are the helper row cid. Questions and approvals raised by a helper already
  carry `meta.helper`; they still render as ordinary cards in the thread.
- `helpers.live()` is not exposed over IPC. The renderer reads working helpers from their synced
  `chat_item` rows, which is enough for Home and survives a restart. Add `live()` only if a future
  screen needs process state that the rows do not carry.
