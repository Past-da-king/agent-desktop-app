# M5 report: onboarding live

## What was built

The four onboarding steps now do real work through `window.agent`, with the same screens and copy as
`design/mockup.html` lines 707 to 794.

- Sign in / Create account: one segmented `role="tablist"` control, labelled Email and Password fields, an
  inline error line in plain words, and a server-side result that never auto-advances. The three server cases
  now read exactly as the milestone asks: 409 "There is already an account with that email. Try signing in.",
  401 "That email and password do not match.", network "Could not reach the sync server. Check the address,
  or use this computer only." An Advanced disclosure holds "Server address" and an "Allow unencrypted HTTP for
  this server" switch. An empty address makes the server refuse, opens Advanced, puts the explanation under
  the field and moves the cursor into it. "Use this computer only, no account" signs out, remembers the choice
  and goes straight to the AI step. The phone QR stays disabled with "Coming soon".
- Already signed in: when settings say signed in (the token was saved by M3), the same step shows
  "Signed in as <email>" with Continue (to the sync step) and "Use a different account" (signs out first).
- Sync: runs `account.firstSync()` once, subscribes to `account.onProgress`, and ticks the four rows
  (Memory, To-dos and goals, Routines, Chats) with real per-entity counts. A fresh/computer-only install shows
  the clean-start copy. A failed pass shows the message plus a real Retry and "Skip for now"; Continue is only
  enabled when the pass finished (and the skip path moves on). Choosing this computer only skips the step.
- AI: providers come from `settings.providers()` and all eight are shown as real buttons (M4 showed six); the
  model field is prefilled from the chosen provider's default and is editable. The key is sent to
  `settings.setApiKey`, then removed from React state before `settings.checkKey()` runs. Check key reports ok or
  failed with the provider's message. The final Continue is disabled until a check passed; the explicit
  "Skip, I will add it later" link is the only other way forward. Subscription rows stay disabled "Coming soon".
  Choosing "Other (OpenAI-compatible)" reveals Base URL and an unencrypted-HTTP opt-in. The steps list keeps a
  real "Open <provider>" link.
- Style: your name, agent name, accent swatches, mascot picker and live preview. "Open Agent" saves every
  choice with `onboarded: true`, clears the onboarding session state, and routes to `#/home`; Home plays a
  one-shot wave animation on the mascot.
- Back navigation sits next to the progress dots on every step after sign-in. The current step and the
  computer-only choice live in `sessionStorage`, and boot falls back to the saved step when the hash is empty,
  so a reload mid-onboarding comes back to the same screen.

## Decisions and deviations

1. The browser mock still accepts an empty server address. The real `AccountService` refuses it and the screen
   opens Advanced and focuses the field, but the gate's Playwright walk (and the demo preview) never types an
   address and has to get through. This is the one deliberate platform difference; it is the mock's contract,
   not the real app's.
2. During onboarding the background sync loop is not started by `signIn`; `firstSync()` runs the visible pass
   and starts the loop afterwards. Otherwise the loop would consume the first pull before the sync screen
   subscribed and every row would show zero. As a second guard, the done counts fall back to the rows the local
   store actually holds, so a reload mid-sync still shows real numbers.
3. Two buttons replace the mockup's single Check key that became Continue, because the accessible-name
   contract names both. After a passing check the Check key button turns tonal so Continue is the single
   primary action.
4. The existing account test asserted the old 401 sentence; it was updated to the milestone's exact copy.
5. "Use this computer only" skips to AI, not to Sync (the milestone asks for the skip). The Sync component also
   redirects there if it is reached after the choice.
6. The step is remembered in `sessionStorage` rather than settings, because a half-finished onboarding is a
   window state, not a preference. The computer-only flag is stored the same way.
