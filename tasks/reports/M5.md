# M5 report: onboarding live

## What I built

The four onboarding steps now do real work through `window.agent`:

- **Sign in.** Sign in / Create account segmented tabs, email and password validation, password show/hide, and
  the server's errors in plain words (409 already exists, 401 no match, network unreachable). "Advanced" holds the
  Server address and an "Allow unencrypted HTTP" switch; an empty address shows the explanation and focuses the
  field. "Use this computer only, no account" signs out, marks the session as local-only, and goes straight to the
  AI step. The phone QR card stays disabled with "Coming soon". If a saved token exists the step instead shows
  "Signed in as <email>" with Continue and "Use a different account".
- **Sync.** Calls `account.firstSync()` and folds `account.onProgress` events into the mockup's four rows, using
  the real per-kind counts. An error shows Retry and Skip for now, and Continue only unlocks when the pass finished
  or was skipped. The step asks `account.status()` for the signed-in state instead of trusting a settings event
  that may still be in flight right after sign-in.
- **AI.** Provider chips come from `settings.providers()`, with a model field prefilled from the provider default
  and editable. The key goes to `settings.setApiKey` and is cleared from React state on submit. "Check key" saves
  the provider, model and optional base URL first, then calls `settings.checkKey()`. Continue needs a passing check;
  "Skip, I will add it later" is the explicit way past it. Subscriptions stay disabled. Custom reveals Base URL and
  the HTTP opt-in.
- **Style.** Name, agent name, accent swatches, mascot picker and a live preview. "Open Agent" writes
  `onboarded: true` and routes to `#/home`.
- Back navigation on sync, AI and style, with the existing progress dots. The step already lives in the route hash
  and the sign-in draft plus the local-only choice live in sessionStorage, so a reload mid-onboarding resumes where
  the person was.

Supporting changes: `AccountService` now returns the exact M5 wording for the three sign-in failures, `Field` accepts
an optional input ref (used to focus the server address), and the phone-width rules wrap the subscription rows so
their labels and "Coming soon" pills do not crush each other at 390px.

## Tests

Added `apps/desktop/test/onboarding-flow.test.ts`, which runs against the real fake sync server: register, seed rows
from a second device, restart the account service, assert the per-kind first-sync progress events and the applied
rows, then save the style-step settings and read `onboarded` back from disk. It also covers the 409, 401 and
unreachable-network messages. Also updated the existing wrong-password expectation to the new wording. 110 tests
pass.

## Not finished / deviations

- The browser mock (and only the browser mock) accepts an empty server address. The real Electron app blocks it and
  focuses the field as M5 asks. This is needed because `scripts/shoot.mjs` walks the preview flow without filling a
  Server address and the mock has no server to reach. The deviation is commented in `SignIn.tsx`.
- I did not add a dedicated waving entrance animation on Home after "Open Agent"; the mascot already renders in its
  animated busy state there. Nothing else from M5 was skipped.
- The subscription rows in the phone-width AI step now wrap the "Coming soon" pill onto its own line. This is a
  responsive fix only; colours, type and spacing tokens are unchanged.

## For the next milestone

- Chat can assume `Settings.onboarded` is only true after a real finish, and that `signedIn` may be false by design
  ("this computer only").
- `AccountService.firstSync` emits `connecting`, then `pulling` with cumulative per-entity counts, then `done` or
  `error`. The sync screen is built against that shape.
- `Field` now takes `inputRef` for focusing. Keep button names from the M5 accessible-name contract when touching the
  onboarding screens, because the gate's screenshot walk depends on them.
