# M1 report: Core models, providers, loop

## Built

- `packages/core/src/model.ts`: `Role`, the `Block` union (`text`, `call`, `result`, `reasoning`, `image`) with the
  same field names as the Kotlin JSON, `Msg`, `msgText`, `msgToolCalls`, `userMsg`, `msgToJson`/`msgFromJson`,
  `ToolSpec`, `Tool`, `ToolContext`, `Usage`, `Completion`, `ProviderException` and `LlmProvider`. The schema helpers
  are `schema`, `str`, `int`, `bool`, `enumOf` and `strList`.
- `http-policy.ts`: `isHttp`, `isLoopback`, `blockReason` and `check`, with the Kotlin message for plain HTTP.
- `providers/http.ts`: `postJson` using global `fetch`, `User-Agent: agent-desktop/1`, three attempts by default,
  retry only on 429, 5xx and network failures, 1.5 s times the attempt number between tries, and the
  `HTTP <status>: <message>` error format.
- `providers/anthropic.ts`: Messages API port (`x-api-key`, `anthropic-version`), text and tool-call parsing, usage,
  base64 images read only when the request is built, and the HTTP policy check.
- `providers/openai-compat.ts`: Chat Completions port with reasoning echo, Gemini `thought_signature` echo and the
  documented placeholder, extra body fields, extra headers, image data URLs and usage.
- `providers/catalog.ts`: the eight providers from `Settings.kt` with ids matching `ipc.ts`.
- `providers/factory.ts`: `providerFor`, including DeepSeek's thinking switch and the OpenCode session header.
- `repair.ts`: `repair` and `flatten`, ported line for line (interrupted stubs, stray results dropped, current turn
  kept whole).
- `trim.ts`: `trimFit` with `BUDGET = 350000` and `KEEP_RECENT = 8`, never cutting text or the recent messages.
- `loop.ts`: `AgentLoop` with the incoming steer inbox, trim before every step, one flatten-and-retry on a 400 that
  mentions "tool", sequential tool execution, unknown tools and thrown errors as error results, the 24,000 character
  clip, `[[image:...]]` markers, an abort check before every step, optional hooks and a step cap.
- `index.ts` re-exports every module.

## Tests

`packages/core/test/` now has `fake-ai.ts` (one local server that speaks both Anthropic and OpenAI shapes), plus
`providers.test.ts`, `repair.test.ts`, `trim.test.ts`, `loop.test.ts` and `msg-json.test.ts`. The fake records every
request so the providers are tested on the real wire format. 36 tests pass.

`bash scripts/gate.sh M1` prints `GATE M1 PASSED` (typecheck, build, repo rules, 36/36 tests).

## Notes for the next milestone

- `ToolContext` now includes `approve(summary, details?)` and `signal`, as PLAN.md section 5 requires. `activity` and
  `updateActivity` use `number` ids, matching the Kotlin `Long`.
- The OpenAI `X-Title` header for OpenRouter says "Agent desktop" instead of the phone's "Phone agent"; it is display
  metadata only. The catalog key hints use plain `...` instead of the Kotlin ellipsis.
- The loop does not call `onAppend` for steer notes, because the Kotlin does not either. If M6 needs the steering text
  in the stored transcript it should persist it when it reads the inbox.
- Aborting is checked before each step and before the next provider call. A tool that throws after the signal is
  aborted ends the run cleanly with the last assistant text.
- No new dependencies were added.
