# M3 report: main process, store, settings, secrets, IPC

## Built

- `apps/desktop/src/main/db.ts`: `Store implements SyncStore` over `node:sqlite` `DatabaseSync`.
  Creates the `rows` / `kv` tables with WAL, keeps one HLC seeded from a device id stored in `kv`,
  and provides typed `list` / `get` / `upsert` / `remove` / `clearAll` plus `onChange`.
  `list` returns live rows ordered by `createdAt` then stamp. `upsert` generates a uuid, keeps
  `createdAt` on update, moves `updatedAt` for memory and task rows, fills sensible defaults for a
  partial row and writes a new HLC stamp. `remove` is a tombstone. `applyRemote` skips this
  device's echo, folds the remote stamp into the clock, applies last-writer-wins and emits one
  change event per entity touched. `localChanges` filters on a local/dirty flag so a pulled row is
  never pushed back.
- `apps/desktop/src/main/settings.ts`: `SettingsStore(file)` merging the file over
  `DEFAULT_SETTINGS`, validating every key and type, ignoring unknown keys, clamping strings to 500
  characters, writing through a temp file plus rename, and emitting `onChange`. `deviceName`
  defaults to `os.hostname()` and is persisted on first read. `reset()` restores defaults.
- `apps/desktop/src/main/secrets.ts`: `Secrets(dir, safeStorage)` with `get` / `set` / `delete` /
  `encryptedAtRest`. Encrypted bytes when the OS keychain is available, otherwise a plain 0600 file
  under a 0700 folder. Names are validated so they cannot escape the folder.
- `apps/desktop/src/main/account.ts`: `AccountService` tying the store, settings, secrets and
  `SyncEngine`. Validates email, password and server address before any call, registers or logs
  in, stores `syncToken` only in secrets, saves `syncUrl` / `syncEmail` / `signedIn`, starts the
  engine, maps 401/409/network failures to plain words, emits status and per-entity `SyncProgress`
  counts, and resumes the long-poll loop from a saved token on construction.
- `apps/desktop/src/main/ipc.ts`: `registerIpc` with a handler for every callable `AgentApi`
  method, argument validation, event broadcasting (`agent:evt:...`), a real `checkKey` completion
  call through `@agent/core`, provider catalog, and a reset that clears the database, settings and
  secrets. `chat.*`, `routines.*` and `files.pick` / `pickFolder` answer "not implemented yet".
- `apps/desktop/src/shared/channels.ts`: the channel names shared by main, preload and the contract
  test.
- `apps/desktop/src/preload/index.ts`: the full `window.agent` over `ipcRenderer.invoke`, every
  `on*` returning an unsubscribe, and `files.pathsFor` using `webUtils.getPathForFile`.
- `apps/desktop/src/main/index.ts`: services created under `app.getPath('userData')` before the
  window, real window controls through IPC, window size/position/maximised state remembered in
  `window-state.json`, `AGENT_SYNC_URL` used only when no saved address exists, cleanup on quit, and
  a smoke check that also awaits `window.agent.settings.get()`.

## Deviations and decisions

- The `rows` table has one extra column, `local INTEGER NOT NULL DEFAULT 0`, beyond PLAN.md 4.1.
  Without it a row pulled from another device would be eligible to push straight back. M2's report
  called this out. The named columns and their meanings are unchanged.
- `SyncEngine.syncOnce()` now aborts an in-flight long poll before taking the mutex, and a loop pass
  checks the loop's abort signal before starting a push/pull. Without this a manual sync or the
  onboarding `firstSync` could wait the full 25 s window, and `stop()` could let one more pass run
  after sign-out.
- `electron.vite.config.ts` excludes `@agent/core` from dependency externalisation for the main
  target. The workspace package ships TypeScript source, so externalising it left a runtime
  `require('@agent/core')` that Electron could not load.
- `vitest.config.ts` aliases `@agent/core` to its source entry so app tests import the same code the
  app builds.
- `files.pathsFor` is local to the preload (it needs real `File` objects), so it has no IPC handler.
  The contract test lists it with the other local methods rather than with the handlers.
- No new dependencies.

## Notes for M4

- `window.agent` is now real for settings, account, data, window and shell. Chat, routines and file
  picking still throw "not implemented yet"; the browser mock bridge stays the source of demo data.
- The real app starts with an empty database and default settings (`onboarded: false`), so the
  renderer should route to onboarding on a fresh install.
- Data events are per entity. The renderer can subscribe once with `data.onChanged` and reload only
  the list it shows.
- The store writes are synchronous SQLite under async methods; keep IPC handlers on the main
  process as they are and do not add file paths from the renderer without validation.
- On Windows the rename in `settings.ts` and `window-state.json` is a normal replace; the code
  already treats a failed write as non-fatal.
