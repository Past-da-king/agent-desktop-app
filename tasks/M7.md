# M7: Home, Tasks, Memory, Routines live

Goal: the four data screens work on real data, edits sync, and routines run by themselves.

Read first: `design/mockup.html` Home/Tasks/Memory/Routines (lines 817-962), `reference/phone/Db.kt` (TriggerRow), `reference/phone/tools/` for routine semantics.

## Build this
- Home: greeting with the user's name and time of day; "Right now" hero (wavy progress) shows the active run or the most recent agent work; "Needs you" (amber) from waiting question/approval cards with the answer chips and Approve inline;
  to-dos (owner user, open, ordered by due) with add (inline field), check, edit (dialog), delete (with an undo toast, not a confirm()); goals with rings (done tasks / total); "Coming up" (next routines and due tasks); "This computer" card.
- Tasks: tabs "My to-dos" / "Agent's work"; master-detail; detail edits title, notes, due date (a real date picker built from a small calendar popover, no native date input look-alike hacks: use `<input type="date">` styled with tokens if the popover is too large), status, goal, blocker; create/delete.
- Memory: list with search (debounced 150 ms, searches title+body+topics), kind filter chips, pinned first; detail view with markdown-lite rendering, clickable `[[Links]]` that navigate (create-on-click offers "Create page"), edit mode (title, kind, topics, body), pin, delete with undo; link graph from the mockup, real links.
- Routines: list (name, schedule in plain words, last run + result, enabled switch), create/edit dialog (kind at/daily/interval, spec controls per kind, prompt textarea), "Run now" button, delete with undo.
- `runtime/scheduler.ts`: wakes every 30 s and on resume-from-sleep; for each enabled trigger computes if due (`at`: time passed and `lastRunAt` null/older; `daily`: today's HH:mm passed and not run today; `interval`: minutes since `lastRunAt`)
  and runs it through the Runner as a ROUTINE-role run (system prompt variant: background, nobody watching, finish with a short summary; `notify_user` allowed; `ask_user`/`request_approval` in a routine post the card and the routine ends with "Waiting for you"), writes `lastRunAt` and `lastResult` (first 300 chars of the final text),
  disables `at` triggers after they run. Never runs two routines at once; missed runs while the app was closed run once on start (not once per missed slot).
  Tools `routine_create`, `routine_list`, `routine_delete` added for the agent (routines created by the agent need `ctx.approve`).
- Notifications (`notify.ts`): `new Notification` for needs-you and routine results when the window is unfocused, click focuses the window and routes to the item.

## Tests
`scheduler.test.ts` (fake clock: due logic for each kind, missed-run catch-up, no overlap, `at` disables itself), `recall`/search tests, routine tools tests, plus store-level tests for goal ring counts.
`shoot.mjs --only data` renders Home/Tasks/Memory/Routines in demo mode AND in an empty (unseeded, onboarded) mode with the empty states, and a "40 items + very long titles" mode (`?demo=big`) to prove truncation and scrolling.
