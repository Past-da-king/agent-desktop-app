# M6: Chat live

Goal: a real conversation with the agent: it thinks, uses tools, asks, requests approval, remembers, and survives a restart.

Read first: PLAN.md section 5, `reference/phone/AgentRuntime.kt` (systemPrompt ~272-355, send/admit ~360+, runTurn), `reference/phone/tools/{CoreTools,MemoryTools,TaskTools,ReportTool}.kt`,
`packages/core/src/loop.ts`.

## Build this (`apps/desktop/src/main/runtime/` and `tools/`)
- `prompt.ts`: `buildSystemPrompt({settings, now, platform, memories, goals, tasks, latestUserText})` per PLAN 5.2, plus `recall.ts` (`rank`).
  Pure function, unit tested (contains the agent name, user name, date line with zone, pinned memories, recalled memories, open tasks; never contains the word "phone" or "Android"; no emoji).
- `tools/memory.ts`: `memory_search(query)`, `memory_get(id)`, `memory_save(title, body, kind, topics, pinned?)`, `memory_update(id, ...)`.
  Results are plain text the model can read (title, kind, topics, body, id). `memory_save` dedupes by exact title (updates instead).
- `tools/tasks.ts`: `task_add(title, owner, goalId?, dueAt?, notes?)`, `task_list(status?)`, `task_update(id, status?, title?, notes?, blocker?)`, `goal_create(title, why?)`.
- `tools/core.ts`: `now`, `ask_user(question, options)` (creates a `question` chat_item and suspends until answered), `request_approval(summary, details)`
  (creates an `approval` chat_item and suspends until decided; declined returns "The user declined."), `notify_user(title, body)` (Electron Notification via an injected `notify`),
  `web_fetch(url, maxChars?)` (GET, https only unless loopback, 20 s timeout, strips HTML to readable text, 12000 chars cap, no cookies, blocks private/link-local IPs after DNS resolution),
  `report(title, markdown)` (creates a `report` chat_item card).
- `runner.ts`: `Runner` per PLAN 5.1. Constructor takes `{store, settings, secrets, providerFactory, tools, notify, emit}` so tests inject a fake provider (use `fake-ai.ts` from core tests, copied/exported
  via `@agent/core/test-utils` or imported by relative path; pick one and keep it simple).
  Behaviour: send/queue, steer inbox merge, persist `turn` rows, activity rows with live status update (`running` -> `done`/`error`), agent text rows, `stop()`, restart safety
  (on startup, any `activity` row still `running` becomes `error: "Interrupted"`; pending cards are re-armed so answering after restart still continues by starting a new turn with the answer),
  error handling (provider failure -> a `notice` row in plain words, `run_finished` with error; never leaves the UI spinning).
  Mode gates: if `settings.ready` is false (no key), `send` inserts a notice "Add an AI key in Settings to start" and does not call a provider.
- Wire `chat.*` handlers in `ipc.ts`; emit `ChatEvent`s; badge/`needs_you` also triggers a notification when the window is not focused and `settings.notifications`.
- Renderer: Chat view uses the real bridge: thread from `data.list('chat_item')` (+ subscription), live "thinking" indicator with the mascot morphing while `running`, tool chips from activity rows,
  question cards with option chips + free text, approval cards (Approve/Decline, >= 44px tall, full-width on phone), report cards that open a reader dialog, stop button while running, attachments chips,
  auto-scroll that does not yank when the user has scrolled up, "New chat" (archives by starting a new `session` marker row kind `notice`... keep ONE ongoing conversation like the phone: New chat just scrolls to a fresh divider; do not delete history).
  Home's "needs you" strip reads real waiting cards.
