# M1: Core: models, providers, loop

Goal: `@agent/core` can hold a conversation with a model that calls tools, against a local fake AI server. Pure Node, no Electron.

Read first: `reference/kotlin-shared/agent/` (Model.kt, Providers.kt, ProviderFactory.kt, Repair.kt, HttpPolicy.kt, AgentLoop.kt) and
`reference/kotlin-shared/data/Settings.kt` (for the provider list).

## Build this (files under `packages/core/src/`)
- `model.ts`: `Role` ('USER'|'ASSISTANT'), `Block` union with a `t` discriminator (`'text'|'call'|'result'|'reasoning'|'image'`, same field names
  as the Kotlin JSON: call `{t,id,name,input,extra?}`, result `{t,id,content,err}`, image `{t,path,mime}`), `Msg {role, blocks}`,
  helpers `msgText(m)`, `msgToolCalls(m)`, `userMsg(text, images?)`, `msgToJson/msgFromJson` (identical JSON shape to Kotlin),
  `ToolSpec {name, description, schema}`, `Tool {spec, run(input, ctx): Promise<string>}`, `ToolContext`, `Usage`, `Completion`,
  `ProviderException` (status, retryable), `LlmProvider`. Schema helpers: `schema(required, props)`, `str`, `int`, `bool`, `enumOf`, `strList`.
- `http-policy.ts`: `blockReason(url, allowHttp)`, `check(url, allowHttp)`, `isLoopback`.
- `providers/http.ts`: `postJson(url, headers, body, {attempts=3, signal, fetchImpl})` with the Kotlin retry rules and `User-Agent: agent-desktop/1`.
  Use global `fetch`. Error message format `HTTP <status>: <message>`.
- `providers/anthropic.ts`, `providers/openai-compat.ts`: ports of `AnthropicProvider` and `OpenAiCompatProvider` including reasoning echo,
  Gemini thought_signature placeholder, `extra` body fields, `extraHeaders`, images as base64 (read the file lazily when building the request).
- `providers/catalog.ts`: `PROVIDERS: ProviderInfo[]` (ids from `ipc.ts`), `providerInfo(id)`.
- `providers/factory.ts`: `providerFor({provider, key, baseUrl, allowHttp, sessionId})` as in `ProviderFactory.kt`.
- `repair.ts` (`repair`, `flatten`), `trim.ts` (`trimFit`, same numbers as Kotlin), `loop.ts` (`AgentLoop` class, `run()` with hooks
  `onEvent`, `onAppend`, `incoming`, plus `signal?: AbortSignal`).
- `index.ts` re-exports everything.

## Tests (`packages/core/test/`)
- `fake-ai.ts`: `startFakeAi(script)` starts an HTTP server on port 0 speaking BOTH `POST /v1/messages` (Anthropic) and
  `POST /v1/chat/completions` (OpenAI). `script` is a function `(requestBody, callIndex) => reply` where reply is
  `{text?, toolCalls?: [{name, input}], reasoning?, status?}`; the server renders it in the right wire format; returns `{url, requests, close()}`.
- `providers.test.ts`: each provider sends the right path/headers/body (assert on the recorded request), parses text, tool calls, reasoning,
  usage; retries on 500 then succeeds; does not retry on 400; refuses plain http to a non-loopback host.
- `repair.test.ts`: missing results get stubs, stray results are dropped, flatten keeps text only before the last user message.
- `trim.test.ts`: old big tool results are cut, recent 8 messages untouched.
- `loop.test.ts`: (1) text-only answer ends; (2) tool call then answer, history has call, result, answer; (3) unknown tool becomes an error
  result; (4) thrown tool error becomes `Error: ...` result; (5) a 400 mentioning "tool" triggers one flatten-and-retry; (6) steer inbox text
  appears in the next request; (7) abort signal stops before the next step; (8) result over 24000 chars is clipped.
- `msg-json.test.ts`: round trip, and a fixture of Kotlin-shaped JSON parses to the same blocks.

## Gate
